# 06 组件选型七大否定判据与高频反模式 (AvoidWhen & Anti-Patterns)

> **“缺的从来不是‘能用什么’，而是‘不该用什么’。”**
> 决定界面专业度的不是正面清单，而是极其严苛的**否定判据 (avoidWhen)** 与 **反模式清单 (doNot)**。

---

## 一、组件选型的七大否定判据 (The Seven AvoidWhen Rules)

当满足以下条件时，必须立即放弃当前组件并转向替代方案（遵循“否定 + 替代 + 理由”原则）：

### ① 量级不匹配 (Volume Mismatch)
- **弹窗内容过多**：弹窗内需要垂直滚动超过 1.5 屏或包含复杂子向导时，**立即改用抽屉 (Drawer) 或独立新页面**。
- **抽屉内容过少**：抽屉仅有一两句说明或极轻确认时，**立即改用对话框 (Modal)**。
- **下拉框选项极少 (建议 < 5 个)**：**立即改用单选框 (Radio) 平铺**，减少点击步长。
- **单选框选项过多 (> 6 个)**：**立即改用下拉选择器 (Select)**，避免横向挤占或垂直刷屏。
- **只有两个布尔选项**：**用单选框或开关**，严禁使用下拉框。

### ② 频次不匹配 (Frequency Mismatch)
- **高频重复的行内轻确认**：每天可能操作十几次的单项确认，**改用气泡确认框 (Popconfirm)**，避免全屏弹窗反复阻断并打断鼠标连续动线。
- **高频录入的复杂级联**：频繁填写的地址或类别，改用带联想记忆的输入组件，避免让用户一层层点开厚重弹窗。

### ③ 时长阈值 (Duration Thresholds)
- **耗时 < 1 秒的操作**：**严禁展示骨架屏 (Skeleton)**，否则闪烁感极强；直接展示内容或微微等待。
- **耗时 1–3 秒的操作**：用按钮内的轻量 Loading 转圈，**严禁用整页大进度条**。
- **耗时 > 10 秒的操作**：必须展示进度百分比、预计剩余时间，并**必须提供取消与后台运行出口**。

### ④ 重要性错配 (Importance Mismatch)
- **任务关键信息藏在气泡内**：**严禁把完成任务所需的重要提示或错误信息藏在 Tooltip 或 Popover 鼠标悬浮气泡中**！关键信息必须直接外露在界面中。
- **普通录入报错用大弹框**：输入框格式错误，直接在字段正下方红字提示，**严禁弹出一个全局 Alert 或模态弹窗**。
- **高危操作阻力不足**：涉及删除、清空、财产变更时，**严禁用轻飘飘的气泡框**，必须升级为模态对话框，给用户适当的心智阻力。

### ⑤ 语义错位 (Semantic Mismatch)
- **触发动作还是页面跳转？**：当前页原地触发状态改变，**用 Button，严禁用超链接 `<a>`**；跳转外部网站或跨路由独立文档，**用链接，不用伪装成 Button**。
- **子系统主导航还是模块分类？**：跨大功能跳转用侧边导航栏（SideNav），单模块内容切换用标签页（Tabs），严禁在同一个页面嵌套三层不同的横向菜单栏。
- **立即生效还是随表单提交？**：改动立即生效用 Switch，随整表提交用 Checkbox。

### ⑥ 结构前提不成立 (Structure Assumption Failure)
- **标签页前提**：内容必须能被清晰分类、互不依赖且无需横向对比。如果用户必须反复比对两组数据，**立即取消标签页改为垂直平铺**。
- **骨架屏前提**：页面布局和结构必须高度固定。如果内容区块高度高度动态（如瀑布流、长文本），**禁用骨架屏**，改用局部 Spin 加载。

### ⑦ 输入负担过重 (Input Burden)
- **已知强记忆字段**：如身份证号、生日、发票税号，能通过 OCR 自动识别或智能剪贴板粘贴解析的，**绝不让用户逐项手动键入**。

## 二、B 端高频反模式红线清单 (Anti-Patterns Redlines)

在页面生成、审查和交付时，违反以下任一红线即判定为设计不合格：

### 1. 结构与排版反模式
- **[严禁] 卡片套卡片（俄罗斯套娃）**：外层白卡片内部再套一层带边框白卡片，导致层级混乱、边框重叠。
- **[严禁] 页面级标题塞进内容卡片**：PageHeader 必须独立处于整个工作区顶端，不可缩进到内部表格白卡中。
- **[严禁] 无筛选区的死表格**：列表数据超过 10 条却不提供最基本的模糊搜索框与状态下拉。
- **[严禁] 表格无分页或手写粗糙分页**：必须接入规范的分页器组件，包含总数统计与每页条数切换。

### 2. 色彩与 Badge 反模式
- **[严禁] 彩虹配色（无语义滥用）**：为了让卡片好看，红、橙、紫、绿随机分配。
- **[严禁] 用危险红表示“未完成”**：`danger` / `destructive` 只留给严重错误、阻断、扣款等真实高危情境；普通未完成状态用 `info` 或 `warning`。
- **[严禁] 纯深色背景刺眼 Badge**：在密集表格中使用刺眼的纯深色底标签，破坏整体扫描节奏（必须坚守 80% 浅底深字法则）。

### 3. 交互与遮罩反模式
- **[严禁] 表单弹窗点击遮罩直接静默关闭**：用户辛辛苦苦填完 10 个字段，误触空白处导致弹窗关闭且内容彻底清空。
- **[严禁] 审批页的主动视觉诱导**：把“通过”做成亮绿主按钮、“驳回”做成灰按钮，违背客观严肃审批中立原则。
- **[严禁] 阴影被父级 overflow 截断成一条黑线**：容器未留够阴影弥散余量，导致卡片边缘显得极其粗糙和残缺。
- **[严禁] 从零手搓成熟组件**：在项目已存在成熟组件库（如 shadcn/ui、antd）的情况下，擅自用原生 div 和 css 从零手搓弹窗、折叠面板、复杂拖拽与树控件。

### 4. 出海与国际化多语言（i18n / RTL）反模式红线

面向海外全球化市场（欧洲多语言、东南亚、中东阿语等）时，违反以下排版与布局规则将直接导致界面错乱崩溃：

- **[严禁] 写死按钮固定像素宽度（短词膨胀定律）**：
  - IBM 本地化指南经典实证：中文 2 个汉字表达的概念，译为欧系语言（德语、荷兰语、法语）后长度能暴涨到原来的 **2 到 3 倍**（如中文“赞” 1 个字 $\rightarrow$ 德文 “Gefällt mir” 12 个字符 $\rightarrow$ 荷兰语 “Vind ik leuk” 3 个独立单词）；
  - 严禁对操作按钮写死 `width: 80px` 或 `w-20`；必须使用弹性填充（`flex-1`）、自适应宽度带最小限制（`min-w-[80px] w-auto px-4`）或弹性操作栏布局，杜绝按钮换行将下方卡片顶出屏幕。
- **[严禁] 出海表单标签（Label）写死过窄宽度**：
  - 传统固定 `w-24`（96px）左对齐 Label 在出海时必遭单词截断；全球化出海表单首选 **Top-Label 上下结构**（Label 在输入框正上方，左右空间 100% 留给长词扩展）。
- **[严禁] 行高紧缩与盲目加 overflow 削顶（变音符号暗坑）**：
  - 泰语、越南语、阿拉伯语、印地语的文字上下带有复杂的音标声调符号（Diacritics，如 ั, ิ, ุ, ْ）；
  - 严禁设置 `line-height: 1` 或 `leading-none`，多语言行高必须保留 $\ge 1.5$（`leading-relaxed`）；严禁在单行文本容器上滥用 `overflow: hidden`，防止头顶和脚底的音标被无情削掉变成“错别字”或造成业务语义严重失真。
- **[严禁] 物理方位 Left / Right 硬编码（RTL 阿语翻转）**：
  - 阿拉伯语等 RTL 界面需整体水平镜像翻转，代码中严禁写死 `left/right`，必须统一使用 **CSS 逻辑属性 (Logical Properties)**：
    - `margin-left` $\rightarrow$ `margin-inline-start`（Tailwind: `ms-`）
    - `margin-right` $\rightarrow$ `margin-inline-end`（Tailwind: `me-`）
    - `padding-left` $\rightarrow$ `padding-inline-start`（Tailwind: `ps-`）
    - `padding-right` $\rightarrow$ `padding-inline-end`（Tailwind: `pe-`）
    - 返回、前进箭头图标配合 `dir="rtl"` 自动掉头。
- **[严禁] 阿拉伯语镜像盲目全盘翻转（五大强制保持 LTR 特例）**：
  - 阿语整页镜像时，以下 5 种要素**必须强制保持从左往右 (LTR)**，全盘翻转会闹常识笑话：
    1. **视频/音频播放进度条**（时间推进永远向右）；
    2. **音量控制条与滑块**（右移为增大）；
    3. **国际电话号码与手机号**（如 `+86 138...`）；
    4. **代码块与英文技术参数**（Terminal / Code Snippets）；
    5. **纯数字、统计指标与数学公式**。
